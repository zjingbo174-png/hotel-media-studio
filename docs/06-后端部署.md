# 后端部署（Cloudflare Worker + D1）

> 这份文档面向不写代码的同事：照着做，大约 10 分钟可以把「多人协作后端」部署到 Cloudflare，得到一个网址，填进 App 的「设置 → 团队协作」即可。
>
> 部署完成后你会得到类似 `https://hms-api.你的子域.workers.dev` 的地址。数据保存在 Cloudflare 的 D1 数据库里，关电脑也不会丢。

## 0. 开始前准备

1. 一个 Cloudflare 账号（免费注册：<https://dash.cloudflare.com/sign-up>，只需邮箱）。
2. 电脑上装有 Node.js，建议 20 或更高（本项目在 v24 上验证）。在 PowerShell 里输入：
   ```powershell
   node -v
   ```
   能看到 `v20.x` / `v22.x` / `v24.x` 即可。没有的话去 <https://nodejs.org> 下载 LTS 版本安装。
3. 项目文件夹，例如 `D:\项目\计划表项目`。后文的命令都在这个文件夹里执行：
   ```powershell
   cd "D:\项目\计划表项目"
   ```
4. 不需要买服务器、不需要买域名。

> 第一次运行 `npx ...` 时，PowerShell 可能问是否安装 `wrangler`，输入 `y` 回车即可。`wrangler` 是 Cloudflare 的官方部署工具，只在部署时用，不是后端运行依赖。

## 1.（推荐）先在本地跑一遍

部署前先确认代码本身没问题：

```powershell
node scripts/api-test.mjs
```

看到最后一行 `PASS 14 / FAIL 0` 就说明接口、隔离、并发、限流都正常。

再启动本地服务：

```powershell
node server/dev.mjs
```

浏览器打开 <http://127.0.0.1:8787/api/health>，应看到：

```json
{"ok":true,"version":"1","time":...}
```

本地数据在 `server/.data/db.json`（已加入 `.gitignore`，不要提交）。按 `Ctrl+C` 停止服务。

## 2. 登录 Cloudflare

在项目文件夹的 PowerShell 里执行：

```powershell
npx wrangler login
```

- 会自动打开浏览器，点 **Allow / 允许**。
- 如果浏览器没弹出，复制终端里显示的网址到浏览器打开。
- 成功后终端显示 `Successfully logged in`。

以后如果提示未登录，再执行一次这条命令即可。

## 3. 创建 D1 数据库

```powershell
npx wrangler d1 create hms
```

终端会输出类似：

```text
✅ Successfully created DB 'hms'
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

复制这段 `database_id`（只复制引号里的内容）。然后用记事本打开项目根目录的 `wrangler.jsonc`，把：

```jsonc
"database_id": "REPLACE_WITH_D1_ID"
```

替换成你刚才的 id，保存：

```jsonc
"database_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

> 注意：`database_name` 要保持在 `hms`；绑定名 `DB` 不要改，代码里用它取数据库。
>
> 如果关掉终端后忘了 id，可以执行 `npx wrangler d1 list` 再查。

## 4. 在云上建表

```powershell
npx wrangler d1 execute hms --remote --file=server/schema.sql
```

看到 `Executed ... commands` 之类的成功提示即可。这一步只做一次；重复执行也安全（建表语句带 `IF NOT EXISTS`）。

想确认表已经建好，可以执行：

```powershell
npx wrangler d1 execute hms --remote --command "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name"
```

应能看到 `batches`、`members`、`saved`、`tasks`、`templates`、`workspaces`。

## 5. 部署 Worker

```powershell
npx wrangler deploy
```

成功后终端会打印访问地址，类似：

```text
https://hms-api.你的子域.workers.dev
```

把这个网址记下来。打开浏览器访问：

```text
https://hms-api.你的子域.workers.dev/api/health
```

能看到 `{"ok":true,...}` 就说明后端已经在云上跑起来了。

> 以后改完后端代码，只要重新执行一次 `npx wrangler deploy`。
> 如果表结构有变化，再执行一次第 4 步的 `d1 execute`。

## 6. 在前端填写

1. 打开 App，进入 **设置 → 团队协作**。
2. **服务地址** 填第 5 步得到的网址，例如：
   ```text
   https://hms-api.你的子域.workers.dev
   ```
   - 不要以 `/` 结尾；
   - 不要再加 `/api`（App 会自己拼 `/api/...`）；
   - 必须是 `https://`。
3. **工作区码** 填 6 位码（例如 `HQEH8N`）。
   - 第一位同事先点「创建工作区」，把生成的 6 位码发给其他人；
   - 其他人填同一个码 + 各自昵称加入。
   - 工作区码字符集是 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`，没有容易看错的 `0 O 1 I`。
4. 昵称 1–16 个字；同一个人换设备时重新用同一工作区码 + 新昵称加入即可（每人有独立 token）。

> 工作区码就是加入凭证，等同于「房间钥匙」。不要发到公开群或截图到公开平台；需要换人时可让成员退出后重新建工作区。

## 7. 本地自测命令

```powershell
# 跑集成测试（不启动端口，直接跑 handler + JSON 存储）
node scripts/api-test.mjs

# 启动本地后端，默认 http://127.0.0.1:8787
node server/dev.mjs

# 换端口（例如 8787 被占用）
$env:PORT=8788; node server/dev.mjs

# 指定本地数据文件位置
$env:HMS_DATA_FILE="D:\temp\hms-db.json"; node server/dev.mjs

# 健康检查
Invoke-RestMethod http://127.0.0.1:8787/api/health

# 用 curl.exe 创建一个工作区（PowerShell 里建议用 curl.exe 避免中文编码问题）
curl.exe -s -X POST http://127.0.0.1:8787/api/workspaces -H "Content-Type: application/json" --data-raw '{"name":"我的团队"}'
```

本地默认允许所有来源跨域（`ALLOWED_ORIGINS=*`）。Worker 上的允许来源写在 `wrangler.jsonc` 的 `vars.ALLOWED_ORIGINS`，默认也是 `*`；如果要收紧，填前端网址，多个用逗号分隔，例如：

```jsonc
"vars": { "ALLOWED_ORIGINS": "https://你的前端.pages.dev,http://localhost:5173" }
```

改完重新 `npx wrangler deploy`。

## 8. 数据、备份与重置

- 云上数据在 D1，删除 Worker 不会删数据；D1 数据库删除才会清空。
- 备份：
  ```powershell
  npx wrangler d1 export hms --remote --output backup.sql
  ```
- 查看数据库列表：
  ```powershell
  npx wrangler d1 list
  ```
- 本地调试数据：`server/.data/db.json`。想从零开始，停掉服务后删除 `server/.data` 文件夹即可。
- 免费额度对 10 人左右的小团队足够用；具体额度以 Cloudflare 后台显示为准。

## 9. 常见报错

| 现象 | 原因 / 处理 |
|---|---|
| `wrangler : 无法将“wrangler”项识别为...` | 不要直接敲 `wrangler`，用 `npx wrangler ...`。 |
| `You are not authenticated` / `Not logged in` | 重新执行 `npx wrangler login`。 |
| `Couldn't find a D1 DB with the name or binding 'hms'` | 检查 `wrangler.jsonc` 的 `database_name` 是否为 `hms`、`database_id` 是否已替换占位符；用 `npx wrangler d1 list` 核对。 |
| 部署时报 `database_id` 相关错误 | `wrangler.jsonc` 里还是 `REPLACE_WITH_D1_ID`，按第 3 步替换。 |
| 浏览器访问 `/api/health` 返回 404 | 地址拼错。应形如 `https://hms-api.xxx.workers.dev/api/health`；先确认 `npx wrangler deploy` 成功。 |
| 接口报 `no such table: workspaces` | 云上还没建表，执行第 4 步 `d1 execute ... --remote --file=server/schema.sql`。 |
| 接口返回 500 | 执行 `npx wrangler tail` 看实时日志；多数是 D1 绑定名不是 `DB` 或表结构没执行。 |
| 接口返回 401 `UNAUTHORIZED` | token 失效或丢失，回「团队协作」重新用工作区码加入。 |
| 接口返回 404 `工作区码不存在` | 码输错（大小写不敏感），或码属于另一个环境/数据库。 |
| 接口返回 429 `RATE_LIMITED` | 触发限流：加入接口 10 次/分钟/IP，创建接口 5 次/小时/IP，写接口 120 次/分钟/IP。等一会儿再试。 |
| 浏览器控制台报 CORS | 检查 `ALLOWED_ORIGINS`；默认 `*`。改成具体域名时不要漏 `https://`，改完重新部署。 |
| 本地 `fetch failed` / 连接被拒绝 | 本地服务没启动，或端口不是 8787；先 `node server/dev.mjs`。 |
| `EADDRINUSE` | 8787 被占用：`$env:PORT=8788; node server/dev.mjs`。 |
| `node` 版本过低 / 没有 fetch | 升级 Node 到 20 或更高。 |
| PowerShell 里中文变成 `????` | Windows PowerShell 5.1 的编码问题，不影响服务器；测试/演示改用 `curl.exe` 或 Node 脚本发送请求。 |
| `npx` 下载很慢或超时 | 检查网络/代理后重试；公司网络可先配置 npm 镜像。 |
| `npx` / `npm` 报「因为在此系统上禁止运行脚本」 | Windows 执行策略限制。在当前 PowerShell 窗口先执行 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force`，再用 `npx.cmd wrangler ...`（注意 `.cmd`）即可，不影响系统设置。 |

## 10. 安全提示

- 工作区码是加入凭证，请只发给团队成员。
- 每个成员的 token 只保存在自己的设备上；服务端只保存 token 的 SHA-256 摘要，不存明文。
- 所有接口走 HTTPS；不要在公共电脑上保持登录。
- 服务端不提供跨工作区读取：任务和模板按成员隔离，内容库（saved）按工作区共享。
