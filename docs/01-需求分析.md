## 1. 项目背景与目标

### 1.1 背景

使用者同时承担酒店一线运营与自媒体内容创作，日常存在三个断点：

1. **运营动作靠记忆**：离店房态价格、排房等固定动作每天重复，容易漏、没有留痕，也无法回顾当天到底干完没有。
2. **选题靠临时刷**：抖音/小红书当天的酒店类爆款内容要靠自己刷，刷到什么算什么；看到爆款也说不清"为什么火"，更谈不上迁移。
3. **二创缺方法**：知道某个账号风格能借鉴，但缺一套"拆解 → 改编 → 拍摄"的落地步骤，往往是收藏了就等于学会了。

### 1.2 目标

把三个断点收敛进**一个手机端工作台**，形成"每日执行 → 选题输入 → 二创输出"的闭环：

- **可量化的执行**：每天的固定动作有清单、有打卡、有进度与历史，漏没漏一眼可见。
- **可解释的选题**：每天一批酒店相关爆款，**逐条**给出"为什么火"的结构化归因，并直接产出原创思路。
- **可落地的二创**：每条热点都附带可执行的改编方案（角度、脚本大纲、拍摄清单、发布建议），而不是一句"建议模仿"。

### 1.3 产品目标指标（非验收项，用于上线后观察）

| 指标 | 目标 |
|---|---|
| 每日清单使用率 | 连续 7 天打开打卡 |
| 选题到产出的转化 | 每周至少从「选题灵感」产出 2 条实际发布内容 |
| 二创方案可用性 | 方案中的"脚本大纲/拍摄清单"无需二次加工即可开拍 |
| 单次使用时长 | 3 个页面的日常巡检 ≤ 10 分钟完成 |

## 2. 用户与使用场景

**用户画像**

- 身份：酒店前厅/运营岗位，兼顾账号运营；非专业剪辑，手机为主要设备。
- 设备：手机竖屏（375–430px 宽）为主，偶用平板/电脑。
- 环境：工作间隙使用，网络可能不稳定（酒店内网/电梯间）。
- 技能：会拍会发，不写代码；对"数据从哪来"接受度高，但对"内容是否真实可用"敏感。

**典型场景**

| 场景 | 时间 | 行为 | 页面 |
|---|---|---|---|
| 早班开机 | 08:00 | 看今天要做什么，勾掉"离店房态价格" | 每日计划 |
| 午间碎片 | 13:00 | 刷一遍今日选题，收藏 2 条，复制关键词 | 选题灵感 |
| 晚班收工 | 21:00 | 检查今日进度，看是否有漏项；浏览热点榜定明天拍什么 | 每日计划 + 热点榜单 |
| 拍摄前 | 次日 | 打开某条热点的二创方案，照着脚本大纲拍 | 爆款热点/二创 |

## 3. 已确认的关键决策

| 决策项 | 结论 | 影响 |
|---|---|---|
| 数据来源 | **首版内置演示数据（Mock），并预留 `ContentSource` 数据源适配器** | 当天可跑通完整体验；后续可替换为真实数据源且 UI 零改动；规避抓取合规风险 |
| 技术形态 | **纯前端单页应用 + PWA**，数据存本地 IndexedDB | 零后端、零服务器成本、可离线；天然适配 GitHub Pages |

| 时区 | **固定 Asia/Shanghai（UTC+8）**，不随设备时区漂移 | 见 §6.1.2 |
| 提醒 | **下班前未打卡提醒纳入首版**（应用内提醒 + 可选浏览器通知，能力边界见 §6.7） | 见 §6.7 |
| 产品名 | **酒店自媒体创作工作台** | 仓库名建议 `hotel-media-studio` |
| 使用者 | **本人 + 最多 10 人小团队**（v0.4 变更） | 保留本地模式；新增在线协作模式，无密码 |
| 协作形态 | **共享内容库 + 各自打卡** | 选题/热点批次、收藏库共享；清单、打卡、提醒按人隔离 |

## 4. 范围界定

### 4.1 首版（MVP，本次开发范围）

- 三页功能完整可用：每日计划、选题灵感、爆款热点/二创
- 移动端优先的响应式布局 + 纵向导航（样式可选，见 §5.2）
- Mock 数据源：**≥ 12 条选题、≥ 10 条热点**，覆盖抖音/小红书两平台、酒店多场景；每条均含完整归因与方案
- 本地持久化（IndexedDB）、离线可打开、可"添加到主屏幕"
- 批次刷新机制（**手动刷新按钮 + 打开时补刷**）、加载/空/错误三态
- 内容库（收藏/已用，跨批次保留）、设置页、数据导出与导入恢复
- 首次使用引导 + "演示数据"知情提示
- 下班前未打卡提醒（应用内提醒条 + 可选浏览器通知）
- 文档与开源配套：README、需求文档、数据源接入说明、LICENSE、免责声明

### 4.2 后续版本（V2+，不在本次范围）

- 真实数据源接入（粘贴链接半自动解析 / 第三方数据 API）
- 内容日历：把选题排期到具体发布日
- 发布后数据回流看板（播放/涨粉）
- 云端同步与多设备、多人协作
- 真正的后台推送（Web Push + 服务端），首版提醒仅在应用打开/后台运行时生效

### 4.3 明确不做（Out of Scope）

- **不做全自动爬虫**：不实现抖音/小红书登录态抓取、签名逆向、批量下载。原因见 [数据源与合规调研](./02-数据源与合规调研.md)。
- 不做账号注册/登录、支付、多人协作。
- 不做视频剪辑、AI 生图/生视频能力。
- 首版不做深色模式、多语言（列为可选优化）。

## 5. 信息架构与导航

### 5.1 一级导航（3 项，纵向）

| 序号 | 菜单 | 图标语义 | 路由 |
|---|---|---|---|
| 1 | 每日计划 | 勾选框/日历 | `/plan` |
| 2 | 选题灵感 | 灯泡 | `/inspiration` |
| 3 | 爆款热点视频/二创 | 火焰/上升箭头 | `/hotspot` |

辅助入口：`/plan/history`（历史与统计）、`/library`（内容库）、`/settings`（设置），均从对应页面右上角进入，不占用一级导航。

### 5.2 移动端导航形态（原始需求 vs 体验的取舍）

原始需求是"左侧纵向导航栏 3 个菜单"，本项目默认**尊重该形态**，同时提供备选：

| 断点 | 形态 | 说明 |
|---|---|---|
| ≥ 768px（平板/电脑） | 左侧栏 **200px**，图标 + 文字 + 选中态 | 桌面标准形态 |
| 400–767px | 左侧栏 **60px** 纯图标 + 10px 标签 + 选中高亮；页面标题显示在顶部栏 | 375px 屏下内容区约 315px，卡片流仍可用；图标必须有 `aria-label` |
| < 400px（可选，默认关闭） | 底部 Tab（3 项，拇指热区） | 设置项"导航样式"可切换；首启动按屏宽给出推荐但不强制 |

**结论**：默认左侧窄栏（符合需求），「底部 Tab」作为设置项提供；实机试用手感不佳再切换，不需要改代码。

### 5.3 二级结构

```
每日计划  /plan
 ├─ 今日清单（默认视图）
 ├─ 新增/编辑任务（底部弹层）
 ├─ 历史与统计（/plan/history：月历 + 当日只读详情）

选题灵感  /inspiration
 ├─ 今日选题列表（平台筛选 / 排序）
 ├─ 选题详情（全屏抽屉：归因 + 原创思路 + 跳转原内容）
 └─ 内容库（/library：收藏、已用，跨批次）

爆款热点  /hotspot
 ├─ 热榜 Top10（排名变化）
 └─ 热点详情（全屏抽屉：风格拆解 + 3 套二创方案 + 跳转入口）

设置  /settings
 └─ 刷新时段、导航样式、数据源说明、导出/导入、清空数据、关于与免责
```

## 6. 功能需求

### 6.0 通用交互约定

- **手势优先级**：列表下拉刷新仅当列表位于顶部且纵向位移 > 70px 时触发；详情抽屉的下拉关闭**仅从抽屉把手/顶部 56px 区域起手**，抽屉打开时禁用背景列表刷新。
- PWA 独立窗口下无浏览器原生下拉刷新，应用自绘刷新指示器；iOS 左缘返回手势与左侧导航栏不冲突（栏内点击优先，边缘滑动仅作用于页面返回）。
- 所有异步操作有加载态；数据读取失败有可重试的错误态；空状态给引导文案。
- 页面切换保留滚动位置与筛选状态。

### 6.1 每日计划

#### 6.1.1 功能清单

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| P-01 | 每日清单自动生成 | P0 | 首次进入自动创建"今天"的清单，预置 2 条：**离店房态价格**、**排房** |
| P-02 | 勾选打卡 | P0 | 点击整行或复选框切换完成态；完成项划线 + 降透明度 + 记录完成时间；再次点击可取消 |
| P-03 | 完成进度 | P0 | 顶部进度显示 `已完成/总数` 与百分比，随打卡实时更新 |
| P-04 | 新增任务 | P0 | 底部弹层：任务名（必填 ≤30 字）、备注（选填 ≤100 字）、"设为每日固定"开关（默认关） |
| P-05 | 删除任务 | P0 | 滑动/长按出现删除；二次确认 + 5 秒内可撤销 |
| P-06 | 编辑任务 | P1 | 修改名称/备注/固定属性；不影响历史记录 |
| P-07 | 排序 | P2 | 长按拖动调整顺序，顺序写入本地 |
| P-08 | 跨天切换 | P0 | 固定 Asia/Shanghai 自然日；跨 00:00 后首次打开自动生成新一天清单（来自"每日固定"模板） |
| P-09 | 未完成项处理 | P1 | **已确认：不自动带入，只保留历史记录**；次日清单只按"每日固定"模板生成，未完成项保留在历史里可查 |
| P-10 | 历史与统计 | P1 | 月历视图：颜色深浅表示完成率；点某天看只读清单；显示连续全勤天数、本周完成率 |
| P-11 | 空状态 | P1 | 清单为空时引导"添加第一条任务" |
| P-12 | 离线可用 | P0 | 断网也能打卡（数据本就在本地） |
| P-13 | 打卡提醒 | P0 | 下班前（默认 18:00）仍有未完成项时提醒，见 §6.7 |

#### 6.1.2 关键规则（统计口径，必须唯一）

1. **时区**：一律按 `Asia/Shanghai` 计算"今天"，**不随设备时区变化**。实现上注入可替换的 `clock`（默认系统时间 + 固定时区格式化），便于测试"时间旅行"。
2. **数据粒度**：清单以"日期 + 任务"为一条记录，同一天同一任务不重复生成。
3. **预置任务**：仅在首次使用时初始化，写入"每日固定"模板；用户删除后不再自动复活。
4. **分母锁定**：当日进度分母 = **该日清单生成完成时的任务条数**（快照值），当日中途新增/删除任务会调整当日的 `plannedTotal`，但历史日期不再变化。
5. **统计只派生不存储**：`dailyStats` 不作为独立真值存储，一律由当日任务快照派生，避免双写不一致。
6. **0 任务日**：当日清单为空（用户全部删除且未新增）时，该日完成率记为 `null`，**不计入**连续全勤天数、不计入本周完成率分母。
7. **模板变更**：修改"每日固定"模板只影响**未来**日期，不回算历史。
8. **撤销**：删除先隐藏、5 秒后落库。

#### 6.1.3 验收标准

- [ ] 首次打开为当天（Asia/Shanghai）日期，清单内有且仅有"离店房态价格""排房"，进度 0/2。
- [ ] 勾选一条后进度 1/2（50%），取消回到 0/2；刷新页面状态不丢。
- [ ] 新增自定义任务后出现在末尾并计入分母；删除可在 5 秒内撤销。
- [ ] **时间旅行用例**：把注入时钟推进到次日 00:01 并重新加载，生成新一天清单；历史日期数据不变；设备时区改为 UTC-5 时"今天"仍按 Asia/Shanghai 判定。
- [ ] 删除当日全部任务后完成率显示为 `—`（非 0%），该日不计入连续全勤天数。
- [ ] 历史页可查看过去任意一天是否全部完成，连续全勤天数与本周完成率按上述口径计算正确。

#### 6.2.1 数据内容（每条选题的字段）

|---|---|---|
| 平台 | 抖音 / 小红书 | 抖音 |
| 标题/文案 | 原始标题或笔记正文摘要 | "酒店前台最怕听到的 5 句话" |
| 作者/账号 | 虚构的演示账号名 | 前台小 A 的日常 |
| 热度 | 点赞 / 收藏 / 评论（Mock 数据标注"示例"） | 12.3w 赞 |
| 发布时间 | 批次日期内的相对时间 | 今天 09:20 |
| 话题标签 | tag 列表 | #酒店 #前台 #职场 |
| 搜索关键词 | 用户可能搜索的词 | 酒店前台、酒店工作日常 |
| 封面 | 本地生成的渐变占位图（不用第三方图片） | — |
| 原链接 | **演示链接**：按该条关键词生成的平台搜索结果页 | 抖音搜索页 |

> **口径说明**：Mock 阶段没有真实原视频地址，因此"一键跳转"落到**平台关键词搜索结果页**，且在卡片与详情上标注"演示链接 · 非原视频"。接入真实数据源后替换为真实 `url`，UI 与交互不变。这是当前阶段唯一的能力降级，必须在界面上如实标注，不得伪装成原视频直达。

| I-05 | 原创创作思路 | P0 | 每条选题 ≥2 个可执行方向（标题建议 + 内容结构 + 拍摄/发布要点） |

| I-10 | 三态 | P0 | 加载骨架 / 空状态 / 失败重试 |
| I-11 | 下拉刷新 | P1 | 手势刷新与「刷新」按钮等效（换一批） |

#### 6.2.3 「火爆原因」分析结构（产品规格）

每条必须覆盖 4 个维度，结论必须**引用该条自己的内容**，禁止模板套话：

1. **选题缺口**：满足什么未被满足的需求（信息差 / 情绪共鸣 / 身份认同 / 猎奇 / 实用清单）。
2. **文案钩子**：开头 3 秒或标题用了什么句式（反问、数字、恐吓、冲突、身份代入、悬念），为何有效。
3. **关键词与话题**：核心搜索词布局、话题借势逻辑、平台推荐机制上的加分项。
4. **形式与节奏**：视频/图文形式、时长、字幕与节奏、封面点击率要素；可迁移的结构。

**质量校验（可机检）**：`npm run check:data` 对每条选题断言——4 个维度字段非空、每条 ≥60 字、`analysis.keywords` 至少回填 1 个该条自带的关键词、`ideas.length ≥ 2` 且每个方向含标题与结构字段。不通过则构建失败。

#### 6.2.4 「原创创作思路」输出结构

每个方向包含：`标题（2 个备选）` + `内容结构（3–5 个节点）` + `酒店场景切入点` + `拍摄/素材清单` + `发布建议（时长/时段/话题）`，确保"看完能开拍"。

#### 6.2.5 交互细节

- 详情抽屉从底部上滑，下拉关闭仅从把手起手（见 6.0）。
- 列表滚动位置在进入详情/返回后保持。
- 安全区适配（iPhone 刘海/底部横条）。

#### 6.2.6 刷新与批次语义（明确能力边界）

已确认改为**手动刷新**（用户点击「刷新」按钮），不做后台定时采集。实现方式：

1. **批次键** `batchId = 日期 + 自增序号`（如 `2026-10-27#2`）。首次打开当天自动拉取第 1 批；用户每点一次「刷新」就产生新一批（序号 +1），演示数据按序号轮转并微调热度，模拟"换了一批采集结果"。
2. 打开应用时若当天还没有批次，自动补刷一次；批次跨天自动失效（`meta.date !== 今天` 时刷新）。
3. 批次信息如实展示：「10月27日 · 第 N 批 · 更新于 HH:mm」，配合"演示数据"角标。
4. 数据来自内置 Mock 数据源；接入真实 API 后同一接口返回即可，`meta.seq` 可改为服务端版本号，UI 无需改动。

手动刷新有 10 秒冷却，避免误触连续请求。

#### 6.2.7 验收标准

- [ ] 当前批次列表展示 12 条（抖音、小红书各 ≥5 条，全部为酒店相关场景）。
- [ ] 平台筛选、排序切换后结果正确，返回列表时状态保持。
- [ ] **全量校验**：12 条中每一条详情都有 4 个归因维度、每维度 ≥60 字且含该条关键词；`check:data` 通过。
- [ ] 每条原创思路 ≥2 条且含标题与结构（自动化断言 + 抽检 1 条人工确认）。
- [ ] 点击"查看原内容"新标签打开平台搜索页，落地页含该条关键词；页面标注"演示链接 · 非原视频"。
- [ ] 下拉/按钮刷新后"最后更新"变化、批次号不变（同批次内容一致）。
- [ ] 收藏后切到下一批次/刷新页面，内容库中仍可见该条。
- [ ] 断网状态已加载数据仍可浏览；点击跳转给出"网络不可用，可复制链接"提示。

## 7. 数据模型（IndexedDB）

| 存储 | 主键 | 关键字段 |
|---|---|---|
| `tasks` | id (`${date}:${uid}`) | date, title, note, done, doneAt, isTemplate, order, createdAt |
| `taskTemplates` | id | title, note, order, active |
| `topics` | id `current` | meta{id,date,seq,fetchedAt,sourceId}, items[] |
| `hotspots` | id `current` | meta{...}, items[] |
| `savedItems` | id (`${kind}:${platform}:${fingerprint}`) | status(saved/used), kind(topic/hotspot), snapshot{}, savedAt |
| `settings` | id `app` | 提醒时间、导航样式、上次提醒日期、数据源、schemaVersion |
| `meta` | key | schemaVersion（数据迁移用） |

**约定**

- 所有记录带 `schemaVersion`；启动时执行迁移函数，不兼容则提示导出并重置。
- UI 不直接依赖存储细节，统一走 `repository` 层，便于将来换远程 API 或云端同步。
- `dailyStats` 不存储，由 `tasks` 派生（见 6.1.2-5）。
- 敏感配置（若将来接入 API Key）只存本地并由用户输入，**不写入仓库、不写入构建产物**。

## 8. 数据源适配器（为后续接真实数据预留）

```ts
interface ContentSource {
  id: 'mock' | 'manual' | 'api';
  label: string;
  // 拉取某天的一批内容；seq 为批次序号（每次手动刷新 +1）
  fetchTopics(date: string, seq: number): Promise<TopicBatch>;
  fetchHotspots(date: string, seq: number): Promise<HotspotBatch>;
  // UI 据此显示"演示数据"角标或"实时接口"标识
  capabilities: { realtime: boolean; requiresAuth: boolean; note: string };
}
```

- `MockSource`：首版实现。以 `date + seq` 为种子轮转演示数据并微调热度，模拟"刷新换了一批"。
- `ManualLinkSource`（V2 预留）：用户粘贴抖音/小红书链接 → 生成一条待分析选题，分析内容人工填写或后续接入模型。
- `ApiSource`（V2 预留）：第三方数据服务或自建服务端接口；密钥由用户本地填写，前端仓库不出现任何密钥。

**数据契约**：Mock 数据用独立 JSON（`src/data/*.json`）承载，字段与 `Topic`/`Hotspot` 类型一一对应；将来替换为 API 返回同一结构，UI 零改动。

## 16. 附录 B：为什么是 PWA 而不是微信小程序

你问到"是不是只能网页浏览、要不要做成微信小程序"，结论是**首版用 PWA，而不是小程序**，理由如下：

| 维度 | PWA（当前方案） | 微信小程序 |
|---|---|---|
| 打开方式 | 浏览器打开 + **"添加到主屏幕"**，有独立图标、全屏无地址栏，用起来接近 App | 微信内搜索/扫码打开，可加到"我的小程序" |
| **一键跳转原视频** | 可直接打开抖音/小红书网页或唤起 App | **做不到**：微信禁止跳出到外部 App，只能复制链接让用户自己粘贴，核心需求直接残废 |
| 部署与成本 | GitHub Pages 免费，推送即发布 | 需注册主体、提交审核（1–3 天/次迭代）、部分能力需企业主体；**无法用 GitHub Pages 开源部署** |
| 通知提醒 | 应用打开时提醒；iOS 16.4+ 安装到主屏幕后可 Web Push（需服务端） | 订阅消息需后端下发，且每次授权只能发一条 |
| 开源 | 代码公开、任何人可自部署 | 代码可开源，但运行依赖微信平台，无法"自己部署一份" |
| 数据存储 | 本机 IndexedDB，可导出导入 | 本机 Storage（10MB 上限），导出不便 |

**如果以后必须要小程序**：可行路径是用 Taro/uni-app 重写壳层 + web-view 承载现有 H5（web-view 需企业主体、业务域名备案），或纯原生重写。届时"跳转原视频"仍只能退化为复制链接。现阶段不建议，因为会牺牲最关键的一键跳转体验。

## 17. 多用户协作（v0.4 变更）

### 17.1 变更与约束

- 使用人数：**本人 + 最多 10 人**（并发 10 个在线成员无压力，服务端为单实例 + D1）。
- 登录：**不设密码、不填邮箱**。凭「工作区码（6 位）+ 昵称」加入，首次加入后服务端签发一个成员 token（32 字节，仅存 SHA-256 摘要），设备本地保存。
- 保留本地模式：不填服务地址时一切照旧，数据只在本机；可随时切换。

### 17.2 数据归属

| 数据 | 归属 | 说明 |
|---|---|---|
| 每日清单 / 打卡 / 每日固定模板 | 成员个人 | 互不可见；接口越权一律 404 |
| 选题灵感、热点榜单批次 | 工作区共享 | 谁点刷新，全组看到同一批（服务端只存 date+seq，内容按种子确定性生成） |
| 收藏 / 已用内容库 | 工作区共享 | 任意成员可增删；跨批次、跨设备保留 |
| 提醒时间、导航样式 | 成员个人 | 随成员设置同步 |

### 17.3 安全设计

- token 仅存摘要；工作区码随机 6 位（32 字符集），加入接口按 IP 限流 10 次/分钟，创建限 5 次/小时。
- 全部写接口按 `workspace_id` 过滤，任务/模板再按 `member_id`；越权返回 404 不泄露存在性。
- 请求体上限 256KB，昵称 ≤16 字、标题 ≤60 字、备注 ≤200 字；`snapshot` ≤64KB。
- 前端只允许 https 的抖音/小红书链接跳转（白名单 + 协议校验），导入备份前做结构、体量、日期格式校验。
- 数据在 Cloudflare D1（免费额度），不接第三方统计；无广告、无追踪。

### 17.4 交互与异常

- 加入/创建成功后自动刷新页面并重新拉取数据；失败时保留原会话并提示具体原因（服务不可达 / 工作区码错误 / 昵称超长）。
- 设置页展示工作区名、工作区码、成员列表与「在线 N 人」（30 秒心跳，120 秒无心跳视为离线）。
- 在线模式下断网：读操作显示上次加载内容，写操作提示失败并保留输入；恢复网络后提示已恢复。
- 在线模式不支持覆盖式导入（避免覆盖他人数据），导入需退回本地模式。

### 17.5 验收标准

- [ ] 两个浏览器分别用同一工作区码加入，A 新建的任务在 B 端不可见；B 的清单只有自己的 2 条预置任务。
- [ ] A 收藏一条选题，B 刷新页面后内容库能看到同一条；B 删除后 A 也看不到。
- [ ] A 点刷新后，B 重新进入选题页看到同一批次号（第 N 批一致）。
- [ ] 设置页显示「在线 2 人」，其中一个离线后 2 分钟内变为 1 人（或标灰）。
- [ ] 错误工作区码 → 明确提示「工作区不存在」；连续错误触发限流提示。
- [ ] 退出工作区后本地模式数据仍在，且不再显示成员信息。
